# wedding-invitations-n8n
# Персональные приглашения на свадьбу в n8n

Тестовое задание: генерация персональных приглашений для гостей старше 25 лет двумя способами, чтобы сравнить архитектуры.

- Оркестрация: n8n Cloud
- База данных: Supabase (PostgreSQL)
- LLM: `openai/gpt-oss-120b` через Groq (бесплатный тариф), в обоих решениях одна и та же модель

## Структура репозитория

```
workflows/
  01-linear-workflow.json              решение 1, линейный workflow
  02-ai-agent.json                     решение 2, AI Agent с tools
prompts/
  prompt-workflow-1.txt                промпт для LLM в решении 1
  system-message-workflow-2.txt        system message агента
  user-message-workflow-2.txt          user message агента
sql/
  schema.sql                           таблица guests и тестовые данные
```

## Решение 1: workflow без агента

Каждый шаг прописан явно, LLM только генерирует текст и ничего не решает.

1. Manual Trigger
2. Supabase, Get many rows, фильтр `age >= 25` (возвращает 8 гостей из 10)
3. Loop Over Items, размер пачки 3
4. Basic LLM Chain + Groq Chat Model: промпт собирается из полей профиля гостя
5. Edit Fields: `guest_id`, `full_name`, `invitation_text`
6. Wait, 60 секунд (из-за лимита токенов бесплатного Groq)
7. Aggregate: все записи в один массив

Результат: массив `{guest_id, full_name, invitation_text}`.

Часть логики считается выражениями в самом промпте, а не моделью: форма обращения ("ты" или "вы"), формат строки про детей, запрет упоминать срок знакомства для родственников, имя без фамилии.

## Решение 2: один AI Agent с tools

Агент сам решает, когда обратиться к базе, как отобрать гостей и когда писать приглашения.

- Узел AI Agent с Groq Chat Model
- Tool `get_guests`: Supabase, Get many rows, таблица `guests`, без фильтра. Гостей старше 25 лет агент отбирает сам
- Structured Output Parser со схемой `{guest_id, invitation_text}`
- Split Out, чтобы получить плоский массив
- В system message описаны цель и правила, но не порядок действий

Результат: массив `{guest_id, invitation_text}`.

## Как запустить

1. В Supabase выполнить `sql/schema.sql` в SQL Editor.
2. В n8n импортировать оба JSON из папки `workflows/`.
3. Создать credentials: Supabase (Host и ключ) и Groq (API key). В репозитории ключей нет, в экспорте только ссылки на credentials.
4. Нажать Execute workflow. Решение 1 работает около 4 минут из-за пауз, решение 2 около минуты.
5. Не запускать оба воркфлоу подряд: лимит Groq (8000 токенов в минуту) общий на модель.

## Сравнение подходов

| | Решение 1: workflow | Решение 2: агент |
|---|---|---|
| Порядок шагов | Задан явно | Агент выбирает сам |
| Фильтр по возрасту | В условии ноды Supabase | Агент отбирает сам из полного списка |
| Запросы к LLM | 8 коротких, по одному на гостя | Один большой на всех гостей |
| Формат результата | Гарантирован структурой нод | Держится парсером и промптом |

## Что наблюдал

- Агент без правил в system message добавил в приглашения дату, время, адрес ресторана, dress-code и просьбу подтвердить участие, а также исказил email. Ничего этого нет в данных.
- Оба решения требовали нескольких итераций промпта. Типичные ошибки: смешение "ты" и "вы", потерянный партнер у родственников, неверная роль гостя ("наш брат" вместо "двоюродный брат невесты"), выдуманный пол ребенка, длинные тире.
- Добавление подсказок-акцентов для разнообразия в решении 1 ухудшило тексты: модель вставляла их дословно. Образцы стиля в промпте работали лучше.
- При одинаковых правилах и образцах качество текстов в двух решениях получилось сопоставимым.

## Выводы

- Для простой и предсказуемой задачи линейный workflow надежнее: формат и порядок шагов гарантированы структурой, легче отлаживать и управлять лимитами.
- Агент оправдан, когда набор действий меняется от запуска к запуску. Цена гибкости: нужен жесткий system message, парсер вывода и проверка результата.
- Качество текста определяет промпт, а не архитектура.
- На более сильных моделях, ожидаемо, качество текстов будет заметно выше, а промпты короче

## Ограничения

- Бесплатный тариф Groq: 8000 токенов в минуту на модель, поэтому в решении 1 стоят паузы.
- Тексты по структуре однообразны, это следствие образцов в промпте.
